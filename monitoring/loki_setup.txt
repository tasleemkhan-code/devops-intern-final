LOKI MONITORING SETUP NOTES
============================

1. How Loki was started (local Docker run)
--------------------------------------------
docker run -d --name=loki -p 3100:3100 grafana/loki:2.9.0 -config.file=/etc/loki/local-config.yaml

This starts Loki on port 3100 using its default local config
(good enough for local/dev use, not for production).

2. Forwarding container logs to Loki
--------------------------------------------
Docker's native Loki logging driver was used to forward the
hello-app container's stdout/stderr logs directly to Loki:

docker run --log-driver=loki \
  --log-opt loki-url="http://localhost:3100/loki/api/v1/push" \
  --log-opt loki-retries=5 \
  --log-opt loki-batch-size=400 \
  devops-intern-final-hello:latest

(Requires the Loki Docker driver plugin to be installed once:
docker plugin install grafana/loki-docker-driver:latest --alias loki --grant-all-permissions)

For a Nomad-deployed job, the same idea applies via Promtail:
Promtail is pointed at the Nomad task's log directory
(alloc/logs/) and configured to push to Loki's push API
(http://localhost:3100/loki/api/v1/push).

3. Command used to view/query logs
--------------------------------------------
Using LogCLI (Loki's command-line query tool):

logcli query '{job="docker"}' --addr="http://localhost:3100"

Or via curl directly against the Loki API:

curl -G -s "http://localhost:3100/loki/api/v1/query_range" \
  --data-urlencode 'query={job="docker"}' | jq

Logs can also be viewed visually by adding Loki as a data
source in Grafana (http://localhost:3000) and using the
Explore tab with the same LogQL query.
